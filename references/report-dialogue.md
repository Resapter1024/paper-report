# Co-developing the report through dialogue

Use this reference for plan, at the beginning of a new report, or when draft pages reveal a substantive narrative choice. This is a focused conversation about the report, not a fixed questionnaire or a dependency on another skill.

## Stage 1: Establish the constraints

Inspect supplied files and prior answers first. Infer the report type when clear; ask when authorship, purpose, or work status would change the presentation.

Choose only the unresolved questions that affect the next decision:

| Choice | Useful information |
|---|---|
| Report type | Paper explanation, self-authored study, course investigation, or research proposal |
| Audience | Relevant courses and concepts they know; what needs introduction; what they should understand after each major step |
| Purpose | What listeners should understand; assignment rubric or required emphasis |
| Time | Total limit, whether Q&A is included, and room for board work |
| Scope | Required topics, material the user wants to explain deeply, and exclusions |
| Practical inputs | Source version, mandatory template requirements if any, languages, user-supplied presenter identity, and protected files |

Ask at most two or three high-impact questions in a round. Present short options when they help the user choose. Avoid questions whose answers can be read from the provided material.

Examples to adapt, not ask verbatim as a batch:

- "Should classmates be assumed to know GLMs, or should we establish that model first?"
- "Does the course assess research design and interpretation, technical derivation, or both? If there is a rubric, use it to decide the allocation."
- "Does the time limit include questions? This affects how much explanation can fit in the main talk."

Without a mandatory external template, use the bundled style rather than asking the user for a reference deck. If presenter identity is missing, ask for it and leave a draft placeholder while other work proceeds; never borrow identity from another report.

Do not make the user explain the paper's novelty or supply a narrative before you have read it. Source reading and proposing an argument are the agent's work. Investigate available material while answers are pending; do not silently settle a materially open constraint.

## Stage 2: Discuss a source-informed narrative

After reading, propose:

1. The central question and the message the audience should take away.
2. The idea or research approach and its supported contributions or findings.
3. A section outline with time allocations and the evidence each section provides.
4. What will be shortened, omitted, or kept as backup.

For the presenter's own report, explain their actual research decisions and findings. Identify whether results are complete, preliminary, reproduced, or planned. Do not demand novelty or convert an unfinished proposal into completed research.

When there is a real tradeoff, offer a recommended plan and a useful alternative. For example, a methods talk might explain the mechanism with one necessary derivation, or spend more time on the theorem and omit an application. A course research report might emphasize design and interpretation, or the implementation choices if these are assessed.

Ask about the decision that changes the report, such as which argument deserves live explanation. Do not ask "What do you think?" without showing the concrete choice and its consequences.

If the user has already specified the direction or authorized you to choose, proceed. Do not turn this stage into a repeated request for permission.

## Stage 3: Improve concrete draft pages

Use a page or section to expose the remaining choice. State what the current draft makes understandable, what is still difficult, and how the available alternatives affect the talk.

Useful discussion includes:

- Whether a particular derivation should be delivered live or explained through its key step.
- Whether a displayed result actually supports the central claim.
- Whether an unfamiliar term needs a concrete introduction before its formal definition.
- Whether the presenter needs a fuller explanation in preparation notes before using a shorter oral version.
- Which supporting material to remove when the time budget is exceeded.

Prefer resolving routine wording and layout issues independently. Ask when the answer changes depth, emphasis, required content, or the presenter's ability to explain the argument.

A question about understanding does not automatically authorize edits. If the user asks for an explanation, answer it; if they request a revision, incorporate the relevant content within that scope.

## Keep the conversation lightweight

Retain the user's decisions, prerequisite knowledge, required introductions, and intended listener takeaways in existing project notes or the page map rather than creating a separate questionnaire document. Carry them across turns and do not ask them again after a page is reordered.

For a narrow revision or export of an existing report, do not restart intake or reopen a settled narrative. Apply only the parts of this process relevant to the change.
